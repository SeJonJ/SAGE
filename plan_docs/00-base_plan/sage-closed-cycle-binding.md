# [Base Plan] SAGE 완결 사이클 결속 차단 + 결속 상시 노출

Cycle-Stem: `sage-closed-cycle-binding`
Risk Level: L3
Status: DESIGN

## 1. Context

장수 브랜치에서 사이클 stem 은 브랜치 leaf 로 **추론**된다. 브랜치를 오래 쓰면 그 leaf 가 가리키는
사이클은 이미 끝나 있고, 그 뒤의 모든 소스 편집이 **완결된 사이클에 조용히 결속**된다. 완결
사이클에는 00~06 문서가 다 있으므로 게이트가 전부 통과한다 — 새 작업이 아무 계획 문서 없이
진행되는데 아무도 모른다.

두 결함은 같은 뿌리의 앞뒤다.

- **J-1**: 완결된 사이클에 새 소스 편집이 결속돼도 막지 않는다.
- **J-2**: OK 줄이 판정 stem 을 **선언했을 때만** 보여준다(`messages._ok_suffix`). 추론으로 결속된
  경우엔 아무 표시가 없어서, 잘못된 결속이 화면에 드러나지 않는다.

J-2 는 선행 조건이 있었다 — claude 런타임의 비차단 메시지가 평문 stdout 이라 사용자에게 닿지
않았다. `hookSpecificOutput.additionalContext` 봉투로 바꾼 사이클이 끝나 조건이 해소됐다.

## 2. Goal

- 추론으로 정해진 stem 이 **완결된 사이클**이면 새 소스 편집을 차단하고, 신규 사이클 또는 명시
  선언을 요구한다.
- 게이트 OK 줄이 판정 stem 과 **그 출처**를 항상 보여준다.

## 3. Non-Goals

- **선언된 stem 은 차단하지 않는다.** 완결 사이클을 명시로 지목하는 것은 의도적 행위이고 이미
  `cycle_stem_declared` 로 감사에 남는다. 추론만 막는다 — 문제는 "모르는 채 결속되는 것"이다.
- **phase 문서 편집은 차단하지 않는다.** 끝난 사이클의 05·06 을 고치는 것은 정상 작업이다.
- 선언 통로 자체의 개선(`sage cycle use`, 머신 로컬 상태)은 다음 사이클 소유.
- 완결 판정용 새 데이터·새 상태 파일을 만들지 않는다 — 재료가 이미 있다(§5).

## 4. 완결의 정의

`report_phase` 문서가 **그 stem 으로** 존재하고 **동시에** `approve_phase` 문서의
`Final Status` 가 `approve_marker` 인 사이클. report 문서의 stem 결속은 필수다 — 아무 06 이나
세면 저장소에 06 이 하나라도 있는 순간 모든 stem 이 완결로 판정돼 대량 과차단이 된다.

**승인을 함께 요구하는 값은 "작성 중인 06 을 걸러내는 것"이 아니다.** report 게이트가 05 승인 없이는
06 을 못 쓰게 하므로, 게이트가 켜져 있던 저장소에서는 `06 존재 ⟹ 승인` 이고 두 조건의 논리곱은
`06 존재` 와 같다. 승인 확인이 실제로 거르는 것은 게이트 설치 전부터 있던 06, override 로 만든 06,
사후에 승인을 되돌린 사이클이다 — 레거시·우회·되돌림 방어이고, 그것으로 충분히 정당하다.
(초안은 이 근거를 "작성 중인 06 오판 방지"로 적었는데 독립 리뷰가 성립 불가임을 지적해 정정했다.)

### 수용한 마찰 — 사이클 마지막 구간

06 을 쓰는 순간 그 사이클은 완결이므로, **그 뒤의 소스 편집은 차단된다.** 보고서를 쓴 뒤 발견한
오타, 버전 범프, 릴리즈 잡일이 여기 걸린다. 사이클당 브랜치를 따는 흐름(이 저장소 자신)에서는 leaf
추론이 **항상 맞는데도** 차단되고, 탈출구는 추론이 이미 내놓은 값을 다시 선언하는 재확인이 된다.

수용하는 근거: 실패 방향이 과차단이고 원인이 화면에 그대로 뜨며(차단 메시지가 stem 을 지목) 탈출구가
한 줄이다. 반대로 이 마찰을 없애려면 "같은 세션에서 06 을 쓴 직후"를 예외로 둬야 하는데, 그건 세션
상태를 판정에 끌어들이는 것이고 "06 을 먼저 쓰고 나머지를 계획 없이 진행" 하는 경로를 그대로 연다 —
이 사이클이 막으려는 바로 그 형태다. 마찰을 남기고 선언이라는 감사 가능한 통로로 처리한다.

## 5. Architecture

새 데이터 없이 기존 재료만 쓴다.

- `profile.pdca` 의 `report_phase` · `approve_phase` · `approve_marker`
- `snapshot.phase_docs[report_phase]` + `cycle_binding.any_document(docs, stem)`
- `snapshot.phase_docs[approve_phase]` + `cycle_binding.select_document` + `_final_status`

판정은 `_decide` 의 cycle binding 블록 뒤에 붙인다(binding 실패가 먼저 걸러진 뒤). 발동 조건:

```text
binding source 가 추론(branch-leaf)이고 선언(event)이 아님 · stem 이 완결
```

phase 변경 0건과 `risk ∈ {L1,L2,L3}` 을 따로 검사하지 않는다. `cycle_binding` 은 phase 변경이 있으면
stem 을 경로에서 얻고 `branch-leaf` 를 출처에 넣지 않으므로 추론 조건이 phase 편집을 이미 배제하고,
그 경우 이 블록에 들어왔다는 사실 자체가 `risk ∈ {L1,L2,L3}` 을 뜻한다. 초안은 두 조건을 명시했는데
변이 테스트에서 **어떤 입력으로도 죽지 않아**(등가 변이) 제거했다. 두 행동은 회귀로 남긴다 —
방어가 어느 줄에 있든 phase 편집과 L0 는 통과해야 한다.

`messages._ok_suffix` 는 stem 이 있으면 항상 렌더하고 출처를 라벨로 붙인다
(선언 / 브랜치 추론 / phase 문서). pdca 비활성이면 stem 이 없으므로 지금처럼 아무것도 붙이지 않는다.

차단은 override 가능하게 둔다 — 기존 `block_cycle_binding` 과 같은 성격이고, 탈출구가
"선언하거나 새 사이클을 시작하라"로 명확하다. Phase 00 복구가 유일 경로인 선언·정합 차단과 다르다.

## 6. Failure Matrix and Required Regression Teeth

차단을 추가하므로 **반대 방향 비차단을 같은 커밋에서 고정한다**(정본 설계 메모 규칙 1).
지적된 입력이 아니라 부류를 닫는다(규칙 2).

- 완결 + 추론 + 소스 편집 → BLOCK. **이 사이클의 기준 회귀.**
- 완결 + **선언** stem → 통과.
- 완결 + phase 문서 편집(05·06 수정) → 통과.
- 완결 + L0 경로 변경 → 통과. **단 세션 위험도 선언이 L0 를 상향시키면 차단된다** — 대상 여부는
  경로 tier 가 아니라 계산 위험도로 갈린다. 두 갈래를 각각 고정한다.
- 완결 + **다른 stem 의** report 문서만 존재 → 통과(내 사이클은 완결이 아니다).
- `approve_marker` 를 커스터마이즈한 프로필에서 그 마커로 완결 판정 · 기본값으로는 판정 안 됨.
- **미완결** + 추론 → 통과. 갈래별로: 06 없음 / 승인 아님 / Final Status 중복 / 승인 문서 없음 /
  승인 문서 모호. 뒤 두 갈래는 "판정 불가" 경로이고, 여기서 fail-closed 하면 아직 끝나지 않은
  사이클의 소스 편집이 통째로 막힌다.
- phase 변경과 소스 변경이 섞인 이벤트 → 차단하지 않는다. **맡길 기존 판정은 없다** —
  `block_report_mixed_evidence` 는 report+dependency 조합만 보므로 phase+소스 혼합을 보는 판정이
  없다. codex 는 한 `apply_patch` 에 둘을 담아 차단을 벗어날 수 있으나(claude 는 툴 호출당 변경
  1건이라 불가), 노력이 공식 탈출구인 stem 선언과 같은 수준이라 실질 위험이 없다.
- pdca 비활성 · report/approve phase 미설정 → 판정 자체가 없다.
- OK 줄: 선언·브랜치 추론·phase 문서 세 출처가 각각 다른 라벨로 보이고, pdca 비활성이면 없다.
- mutation: 완결 조건에서 06 존재 제거·APPROVED 제거, 추론 한정 제거(선언까지 차단),
  phase 편집 예외 제거, `_ok_suffix` 의 선언 한정 복원이 각각 죽는다.

## 7. Acceptance

- 장수 브랜치 실측 형태(브랜치 leaf = 끝난 stem, 새 소스 편집)가 exit 2 로 막히고 안내가
  선언·신규 사이클 두 탈출구를 제시한다.
- 위 부류 전수 통과, 기존 판정 불변.
- none/Claude/Codex 공식 suite, all-kind validate, wheel smoke, mutation, `git diff --check`.
- L3 독립 리뷰. 리뷰는 **과차단 방향**을 공격해야 한다 — 정상 진행 중인 사이클이 완결로 오판되는
  입력을 찾는 것이 이 사이클의 주된 실패면이다.

## 8. Tracking

- 선행: `sage-hook-io-context-envelope`(J-2 의 전달 채널 전제)
- 후속: J-3 선언 통로(`sage cycle use`) — 이 차단의 권장 탈출구를 정식화한다.
