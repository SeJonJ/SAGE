# [Base Plan] SAGE 10-j-2 선언 risk 포착 정밀도와 정정 경로

Cycle-Stem: `sage-declared-risk-precision`
Risk Level: L3
Status: IMPLEMENTED (2026-08-03, 미커밋 · 독립 리뷰 전)

## 1. Context

10-j의 두 번째 사이클이다. 세션 위험도 **선언 통로의 입력 품질**과 **잘못 잡혔을 때의 회복 경로**를
다룬다. 결속 판정과 위험도 계산 규칙은 건드리지 않는다.

`capture-declared-risk`가 **가정 질문**에서 위험도를 선언으로 포착한 실측이 있다(`0.9.77`).

```json
{"level": "L3", "excerpt": "…특정 버그가 있을때 L3 개발을 1차로 한후 추가 개선을 위해 …다시 L2 로 개발을…"}
```

착수 전 소스에서 재확인했다. `capture_declared_risk_core.py:18`의 `_LEVEL_PATTERN_1`은
`L([0-3])\s*(으?로|로|레벨|수준|작업|개발|진행|…)`이고 **의문문·가정문 방어가 전혀 없다.**
`L3 개발`이라는 문자열이면 무조건 포착한다. core 주석은 *"개발 의도 맥락 동반 시에만
(메타 대화 오탐 회피)"*를 의도한다고 적혀 있으나 그 방어는 코드에 없다.

이어서 `levels = [...]` 뒤 `level = max(levels)`(`:60`)가 같은 문장의 L2를 제치고 L3를 채택한다.

### 1.1 실측된 피해 — 오탐 하나가 세션 전체를 멈춘다

포착된 L3는 `event.declared_max`로 게이트에 들어가고, `pre_implementation_gate_core.py:130-133`에서
계산 위험도보다 높으면 그것을 채택한다. 그 결과 세션 전체가 L3로 간주돼 이번 사이클 00의
`Risk Level: L2`를 초과하고 **모든 편집이 차단**됐다. 저장소 밖 Obsidian 위키 편집까지 막혔다.

그리고 안내가 문제를 키운다. `messages.py:116`의 `block_cycle_risk_reconciliation` 힌트는

```
`{phase00_path}`의 Phase 00 Risk Level을 {required_risk} 이상으로 먼저 상향한 뒤 원래 변경을 재시도하세요
```

를 **위험도의 출처와 무관하게 무조건** 제시한다. 실제로는 L2 사이클인데 이대로 따르면
**위험도 기록을 허위로 상향**하게 된다. 게이트가 스스로 기록 오염을 유도한다.

정정 경로는 새 프롬프트로 덮어쓰는 것뿐이고, 잘못 잡힌 선언을 지우는 방법이 없다. 방치하면
`_CLEANUP_OLDER_THAN_SECONDS`(2일)까지 세션이 묶인다.

### 1.2 재료는 이미 있다

- 위험도가 선언에서 왔는지 경로·내용 계산에서 왔는지는 `classify_risk`가 이미 구분한다.
  `pre_implementation_gate_core.py:133`이 선언 채택 시 `trigger_sources`에 `declared_{level}`을
  추가하고, 그 리스트는 차단 판정 시점(`:1038` 인접)에 접근 가능하다. **새 데이터가 필요 없다.**
- 선언 상태는 `.{host}/logs/declared-risk-{session}.json` 한 파일이고 core가 `state_file`과
  `state`를 결정론적으로 계산한다. 삭제 결정도 같은 자리에서 표현할 수 있다.

## 2. Goal

- 의문문·가정문에서 위험도를 선언으로 포착하지 않는다.
- 한 프롬프트에 서로 다른 레벨이 함께 나오면 선언으로 보지 않는다.
- 잘못 잡힌 선언을 사용자가 **한 번의 프롬프트로 즉시** 지울 수 있다.
- 차단 안내가 위험도의 출처에 따라 갈린다. 선언에서 온 위험도면 *선언 정정*을 먼저 제시하고,
  경로·내용 계산에서 왔을 때만 *00 상향*을 제시한다.
- 모호해서 포착하지 않을 때 그 사실을 사용자에게 알린다. 조용한 미포착은 선언했다고 믿은 채
  진행하게 만든다.

## 3. Non-Goals

- **위험도 계산 규칙 불변.** `classify_risk`의 경로·내용·filename 판정, effective-max 조정,
  `_RANK` 비교를 바꾸지 않는다. 결함은 계산이 아니라 입력 품질과 안내다.
- **선언 통로 자체를 막지 않는다.** 장수 브랜치에서는 정상 경로다.
- 결속 판정(J-1·J-2·J-3)과 거버넌스 자산 자기 분류(J-7) — 10-j의 다른 사이클 소유.
- 선언 TTL(2일) 변경. 정정 경로가 생기면 TTL은 안전망으로만 남는다.
- 영어 프롬프트 패턴 확장. 현행 `_LEVEL_PATTERN_2`의 `risk level N` 처리 범위를 넓히지 않는다.
- host별 선언 상태 공유. 지금처럼 런타임별 로그 디렉터리에 남긴다.

## 4. Global Invariants

### G1. 포착은 좁히기만 한다

이번 변경으로 **새로 포착되는 입력이 있어서는 안 된다.** 기존에 포착되던 것 중 일부만 포착되지
않게 된다. 정규식을 느슨하게 만들어 포착을 늘리는 방향은 금지한다 — 오탐이 곧 세션 정지이므로
**미포착보다 오탐이 비싸다.** 미포착은 사용자가 다시 선언하면 되고, 오탐은 2일간 묶인다.

### G2. 안내는 사용자를 허위 기록으로 유도하지 않는다

차단 안내가 제시하는 첫 번째 행동은 **사용자가 실제로 취해야 할 행동**이어야 한다. 위험도가 세션
선언에서 왔다면 00 상향은 기록을 오염시키는 행동이므로 첫 번째로 제시하지 않는다.

### G3. core 순수성 보존

`capture_declared_risk_core.decide(event) -> decision`은 지금처럼 IO 없는 순수 함수다. 파일 삭제도
adapter가 수행하며 core는 `action`으로 표현만 한다. `now_utc` 주입 결정론도 유지한다.

### G4. 기존 선언 상태 호환

이전 버전이 남긴 `declared-risk-*.json`을 읽지 못해 크래시하지 않는다. 형식은 바꾸지 않는다.

## 5. Architecture

### 5.1 포착 정밀도 (core)

`decide()`가 포착 후보를 만든 뒤 두 개의 기각 규칙을 적용한다.

```text
규칙 1  매치가 의문·가정 문장 안        → 그 매치 기각
규칙 2  서로 다른 레벨을 둘 이상 선언   → noop (ambiguous)
남은 매치 0건                           → noop
```

**모호함은 선언 시도의 수로 판정한다.** 접미사 없는 단순 언급(`캐시는 L2 유지`, `L3.java`,
코드블록 주석)은 선언 시도가 아니므로 세지 않는다 — 세면 개발자 프롬프트에서 흔한 레벨 언급
하나가 정당한 선언을 통째로 폐기한다(독립 리뷰가 재현).

**규칙 1이 실측 사례를 직접 닫는다.** `L3 개발 … 다시 L2 로 개발` 은 서로 다른 두 레벨이라
선언이 아니다. `max()`로 하나를 고르는 현행 규칙은 "여러 레벨이 나오면 가장 위험한 것을
의도했을 것"이라는 가정인데, 실측은 그 가정이 틀렸음을 보여준다 — 여러 레벨이 함께 나오는 문장은
**선언이 아니라 비교·설명**일 확률이 높다.

규칙 1은 문장 단위로 판정한다. 프롬프트를 문장으로 쪼개고, 매치가 속한 문장이 의문·가정 표지를
가지면 그 매치를 버린다. 표지는 정책이므로 core 상수로 두고 목록을 코드에 명시한다.

표지는 두 종류로 나눈다. **강한 표지**(`?`, `만약`, `어떻게 되`, `what if`)는 문장 어디에 있어도
질문·가정으로 본다. **종결 어미**(`나요`, `가요`, `할까`…)는 문장 **끝**에서만 본다 — 무경계로
잡으면 `지나가요`·`만나요` 같은 평서형 동사에 걸려 같은 문장의 정당한 선언을 버린다.

문장 분리는 소수점·버전 표기(`3.5`, `L3.java`)에서 쪼개지 않는다. 쪼개면 `만약 3.5 버전이면
L2 로 진행`이 `만약 3.` / `5 … L2 로 진행`이 되고 뒤 조각에 가정 표지가 없어 **오탐**이 된다.

`max()`는 제거하지 않고 **유일 레벨 확인 후의 그 값**을 쓴다. 결과적으로 규칙 통과 시 레벨은
하나뿐이므로 `max()`와 같은 값이지만, 의미가 "가장 높은 것을 고른다"에서 "유일한 것을 쓴다"로
바뀐다.

### 5.2 정정 경로 (core + adapter)

새 `action: "clear"`를 도입한다. 프롬프트가 명시적 해제 표현을 담으면 선언 상태 파일을 지운다.

```text
decide() -> { action: capture | clear | noop, ... }
action=clear  → adapter 가 state_file 을 삭제(없으면 무시), 안내 메시지 출력, exit 0
```

**CLI가 아니라 프롬프트 경로를 고른 이유가 있다.** 선언 상태는 세션 ID로 이름이 붙는데 사용자는
자기 세션 ID를 모른다. 또 선언을 담는 `.claude/settings.local.json` 계열이 게이트에 걸리는
닭-달걀이 이미 실측됐다. `UserPromptSubmit`은 게이트 대상이 아니므로 이 경로에는 닭-달걀이 없다.

해제 표현은 포착 패턴과 **겹치지 않아야** 한다. 레벨을 포함하면 포착과 경합하므로 해제는 레벨 없이
표현하고 clear 판정을 capture보다 먼저 수행한다.

**해제도 포착과 같은 문장 필터를 거친다.** 해제는 안전장치를 끄는 행동이므로 질문
(`해제해야 하나요?`)이나 부정(`해제하지 마`)에서 발동하면 오탐 포착보다 나쁘다 — 사용자가 명시적으로
반대한 방향으로 게이트를 약화시킨다. 부정은 **해제 구절 직후**만 검사한다. 문장 전체를 보면
`L3 아니야 위험도 선언 해제`처럼 부정어가 레벨을 향한 경우까지 거부해 탈출구를 막는다.

### 5.3 안내 분기 (core + messages)

`block_cycle_risk_reconciliation` 판정에 위험도 출처를 싣는다.

```text
decision["risk_from_declaration"] = any(s.startswith("declared_") for s in trigger_sources)
```

`messages.gate_text`의 힌트가 이 값으로 갈린다.

```text
risk_from_declaration = True   1) 이번 세션 선언이 {level} 입니다. 잘못 잡혔다면 <해제 문구>
                               2) 실제로 {level} 작업이면 00 상향
risk_from_declaration = False  현행 문구 그대로 (00 상향)
```

문구는 `messages` 모듈이 단독 소유한다. core는 사실(출처)만 싣고 표현하지 않는다.

## 6. Failure Matrix and Required Regression Teeth

### 6.1 포착 정밀도

- **실측 프롬프트 원문**이 `noop`이어야 한다. 이것이 이 사이클의 기준 회귀다.
- 단일 레벨 평서 선언(`L2 로 진행할게`, `이번 작업 L3 야`)은 그대로 포착된다.
- 의문문(`L3 로 개발하면 어떻게 되나요?`), 가정문(`L3 라고 치면`)은 포착되지 않는다.
- 같은 레벨이 여러 번 나오면(`L2 로 하고 L2 로 마무리`) 포착된다 — 서로 다른 레벨이 아니다.
- `risk level 3` 계열(`_LEVEL_PATTERN_2`)에도 같은 규칙이 적용된다.
- 포착 결과의 `state` 구조와 `excerpt` 절단 규칙이 불변이다.

### 6.2 정정 경로

- 해제 프롬프트가 상태 파일을 지우고 exit 0이다.
- 상태 파일이 없을 때 해제해도 실패하지 않는다.
- 해제 직후 같은 세션의 게이트가 선언 없는 상태로 판정한다.
- 해제 표현이 포착 패턴을 우연히 만족해 **선언으로 잡히지 않는다.**
- adapter가 파일 삭제에 실패해도 traceback 없이 진단을 남긴다.

### 6.3 안내 분기

- 선언에서 온 차단은 안내 첫 줄이 *선언 정정*이다.
- 경로·내용 계산에서 온 차단은 현행 *00 상향* 문구가 그대로다.
- 두 경우의 `status`/`exit_code`/`message_key`가 같다 — 바뀌는 것은 힌트뿐이다.
- 양 런타임에서 같은 분기를 탄다.

### 6.4 Mutation requirements

되돌리면 최소 한 테스트가 **정확한 사유로** 실패해야 한다.

- 다중 레벨 기각 규칙
- 의문·가정 문장 기각 규칙
- `clear` 액션과 adapter의 삭제 수행
- clear 판정을 capture보다 먼저 하는 순서
- clear의 의문·부정 필터
- 종결 어미의 문장끝 앵커
- 문장 분리의 소수점 예외
- 삭제 대상 부재 시의 구분된 안내
- `risk_from_declaration` 스탬프
- messages의 힌트 분기

rc만 같은 다른 결함으로 우연히 통과하는 테스트는 방어선으로 인정하지 않는다.

## 7. Acceptance

- 실측 오탐 프롬프트가 더 이상 선언으로 포착되지 않는다.
- 정상 선언은 그대로 동작한다(회귀 없음).
- 잘못 잡힌 선언을 한 번의 프롬프트로 지울 수 있다.
- 선언에서 온 차단 안내가 00 상향을 첫 번째 행동으로 제시하지 않는다.
- 위험도 계산 규칙과 결속 판정이 불변이다.
- none/Claude/Codex 공식 hook suite, `sage validate --kind all --check --schema`, wheel smoke,
  `git diff --check`, mutation suite가 모두 통과한다.
- L3이므로 Phase 06 전에 독립 리뷰를 받는다. 리뷰는 실제 프롬프트 코퍼스로 포착/미포착을 재현해야 한다.

## 9. Implementation Result (2026-08-03)

- 포착 규칙을 좁혔다. 문장 단위로 의문·가정 표지를 검사해 그 문장의 매치를 버리고, 한 프롬프트에
  서로 다른 레벨이 나오면 포착하지 않는다. `max()`는 유일 레벨 확인 뒤의 값이 됐다.
- 모호함 판정에 선언 패턴이 아니라 **언급 패턴**을 쓴다. 선언 패턴은 접미사를 요구해
  `L1 이나 L2 로 진행`에서 L1을 보지 못했고, 그대로 두면 다중 레벨 기각이 헛돌았다.
- `action: "clear"`를 추가했다. 해제 판정이 포착보다 앞서므로 무엇이 잘못 잡혔는지 설명하며
  해제하는 프롬프트가 다시 선언으로 잡히지 않는다. adapter가 상태 파일을 지우고 core는 표현만 한다.
- `block_cycle_risk_reconciliation`에 `risk_from_declaration`을 싣고 `messages`의 힌트를 갈랐다.
  선언에서 온 차단은 *선언 해제*를 먼저, 계산에서 온 차단은 기존 *00 상향*을 제시한다.

코퍼스 14건으로 포착/미포착을 확인했고 실측 오탐 프롬프트 원문이 `noop`이다. 변이 7종이 모두 의도한
테스트에서 죽었다. 초안에서 해제 순서 변이가 살아남았는데 테스트 프롬프트의 `L3 아니야`가 선언 패턴에
걸리지 않아 순서를 바꿔도 결과가 같았기 때문이다 — 포착 가능한 선언과 해제 문구를 함께 담은 프롬프트로
교체해 죽였다.

runtime·core 변경으로 `hook_runtime_hash`, `canonical_hash` 2건, `spec_hash` 1건이 STALE이 되어
해당 필드만 재스탬프했다. 엔진 루트에서 `sage generate`를 실행하지 않았다.

none/claude/codex run-all, all-kind validate, wheel smoke, compileall, `git diff --check`,
한영 문서 동형이 모두 통과했다. 독립 리뷰와 commit은 아직 수행하지 않았다.

### Phase 05 독립 리뷰 (2026-08-03)

패킷을 포착 규칙 / 정정·안내 두 갈래로 나눠 각각 독립 headless 세션에 맡겼다. **둘 다 FAIL이며
BLOCKER 1건 · MAJOR 2건 · MINOR 2건을 재현했다.** 리뷰 중 작업 트리가 바뀌지 않았음을 파일 해시
351건으로 확인했다. 지적 전부를 재현 검증한 뒤 수용했다.

**BLOCKER — 해제가 질문·부정에서 발동했다.** `위험도 선언 해제하지 않을 거예요`가 선언을 지웠다.
사용자가 명시적으로 반대한 방향으로 안전장치를 끄는 것이므로 오탐 포착보다 나쁘다. 해제를 포착과
같은 문장 필터에 태우고 부정을 배제했다. 부정은 **해제 구절 직후**만 본다 — 문장 전체를 보면
`L3 아니야 위험도 선언 해제`처럼 부정어가 레벨을 향한 경우까지 거부해 탈출구가 막힌다(초안이 그랬다).

**MAJOR — 언급 패턴이 정당한 선언을 폐기했다.** `캐시는 L2 유지, 이번 작업은 L3 로 진행할게요`가
noop이 됐다. 캐시 레벨·파일명·코드블록 주석은 개발자 프롬프트에서 흔하므로 상시 발생이다.
리뷰어의 처방(모호함 판정을 문장 단위로 스코프)은 **수용하지 않았다** — 위 예시는 단일 문장이라
그 처방으로 고쳐지지 않는다. 근본 원인은 언급 패턴 자체이므로 제거하고 모호함을 **선언 시도**의
수로 판정한다.

**MAJOR — 종결 어미가 무경계로 매칭됐다.** `지나가요`의 `가요`가 걸려 같은 문장의 선언을 버렸다.
표지를 강한 표지(문장 어디든)와 종결 어미(문장 끝만)로 분리했다.

**MINOR 2건** — 조합형 한글에 결코 매칭되지 않는 `ㄴ가|ㄹ까` 죽은 패턴을 제거했고, 지울 것이
없을 때 "지웠습니다"로 안내하던 문구를 구분했다.

수정 과정에서 문장 분리가 소수점·버전 표기에서 쪼개지는 문제도 발견했다. `만약 3.5 버전이면
L2 로 진행`이 `만약 3.` / `5 … L2 로 진행`이 되어 가정 표지가 분리되고 **오탐**이 된다 — 리뷰어가
지적한 항목은 아니지만 같은 축의 결함이라 함께 닫았다.

### 재검증 (2026-08-03)

- 코퍼스 25건 전부 의도대로. 리뷰어가 제시한 회귀 6건이 모두 해소됐다.
- **G1을 HEAD 대비로 직접 검증했다.** 레벨 표현 × 문맥 × 종결 조합 462건에서 "이전엔 미포착인데
  지금 포착"인 입력 0건 — 포착이 넓어지지 않았다.
- 변이 11종(다중 선언 기각, 포착·해제의 의문 기각, 종결 어미 앵커, 문장분리 소수점 예외, clear
  액션·순서·삭제·부재 안내, 스탬프, 힌트 분기)이 모두 의도한 테스트에서 죽었다. 초안에서 소수점
  예외 변이가 살아남았는데 테스트 프롬프트의 의문 표지가 뒤 조각에 남아 예외 없이도 통과했기
  때문이다 — 가정 표지가 분리되는 프롬프트로 교체해 죽였다.

### 보완 — 조용한 미포착 제거 (2026-08-03)

리뷰 후 남은 미포착(`로그 레벨은 L2 로 두고, 이 작업은 L3 로 진행할게요`)을 점검하면서 더 큰 문제를
확인했다. **미포착이 완전히 조용했다**(`message_key=None`). 사용자가 선언을 적고 아무 반응이 없으면
그 레벨의 게이트가 걸린다고 믿은 채 진행한다 — 포착 확인 메시지의 *부재* 가 유일한 신호인데 부재는
눈치채기 어렵다.

모호 기각에 `risk_declaration_ambiguous` 안내를 붙였다. 상태 파일은 건드리지 않고 기각 사실만
알리므로 포착이 넓어지지 않는다. 이 hook은 `UserPromptSubmit`이라 exit 0 stdout이 컨텍스트로
올라가는 세 이벤트 중 하나이며, 기존 `render_declared_capture`가 이미 쓰는 검증된 경로를 재사용한다.

변이에 **"안내를 모든 noop으로 확대"** 를 포함했다. 좁히는 방향만 방어하면 잡음 방향으로 넓어지는
회귀를 못 잡는다.

### 남은 한계

`로그 레벨은 L2 로 두고, 이 작업은 L3 로 진행할게요`는 여전히 미포착이다. `레벨은 L2 로`가 선언
패턴과 문법적으로 구분되지 않아 두 선언 시도로 보이기 때문이다. 구분하려면 문맥 이해가 필요하고,
미포착은 G1이 정한 안전한 방향이다. 이제 사용자가 미포착 사실을 알고 레벨 하나만 다시 적으면
해소되므로 이번 범위에서 닫지 않는다.

보완에 대한 재리뷰(포착 규칙 축)는 PASS다. G1 미위반, 잡음 없음, 양 런타임 전달, 상태 파일
미변경을 리뷰어가 재현해 확인했다. MINOR로 지적된 troubleshooting 문구 중복은 **부분 수용**했다 —
사용자 문서와 hook spec은 대상이 달라 일부 재진술이 의도적이지만, 두 번 덧붙이며 불어난 문단과
막힌 사용자에게 불필요한 방어 세부는 줄였다.

`test_install.py`의 force-reinstall 보존 테스트가 run-all 3회 중 1회 실패했다(단독 실행은 통과,
재실행 2회 통과). 이 사이클 변경과 무관한 install 경로이고 원인은 미확정이다. 다만 테스트가
`install.run()` rc를 단언하지 않아 실패가 manifest `FileNotFoundError`로만 나타나 진짜 사유가
가려졌으므로, 재발 시 원인이 보이도록 rc 단언을 추가했다.
