이름표가 붙은 쪽지 묶음을 자동으로 건네고, 압축 뒤에는 다시 건넵니다.

Codex 수동 압축 뒤 재전달을 작은 모의 모델 시험으로 확인했습니다. 양쪽 실제 모델의 작은 표준·Fast 선택 시험도 각 1회 통과했습니다. 실제 프로젝트·자동 압축·큰 입력 검증은 남아 있습니다.

적대적 리뷰 뒤 바뀐 점

“이렇게 하면 깨진다”를 먼저 찾았어요.

1
전달할 상자와 적용할 쪽지를 나눠요.

Codex 훅은 어떤 스킬이 선택됐는지 모릅니다. 그래서 이름표가 붙은 전체 자료를 주고, 호출된 스킬이 자기 칸만 사용하도록 설계합니다.

2
Fast의 문부터 확인해요.

Fast가 허용된 뒤 표준·Fast 쪽지를 한 봉투로 보냅니다. Fast 파일 뒤에 부분 쪽지를 따로 붙이지 않아요.

3
시작 훅 하나에 중단을 맡기지 않아요.

내용 오류·크기 초과는 사용자 입력과 지원 도구 경계에서 막습니다. 일반 텍스트 출력까지 모두 멈춘다는 보장은 하지 않아요.

4
주소와 받는 사람을 같이 확인해요.

다른 프로젝트나 리뷰어에게 부모 작업의 규칙이 잘못 배달되지 않게 해요.

5
새 쪽지와 옛 쪽지를 구분해요.

파일이 바뀌면 실제로 전달한 내용의 표시를 남겨요. 새 읽기에 실패했다고 옛 쪽지로 계속하지 않아요.

일반 모드 문맥에도 Fast 원문은 보입니다. “보인다”와 “적용한다”를 구분하는 설계이며, 모델이 이름표를 잘 따르는지와 전체 묶음의 크기 비용을 검증해야 합니다. 이 경계를 보안 격리라고 부르지 않습니다. 새 방식의 검토·시험 기록

작게 고칠 부분

기존 길을 먼저 고쳐요.

읽기 함수, 기존 훅, 역할별 위임 경로를 재사용합니다. 이번 필수 수리는 스킬 7종입니다.

추가 범위의 제한

큰 관리 시스템은 만들지 않아요.

현재 스킬을 추적하는 DB, 새 런처, 프록시, 사람 인증 서버를 만들지 않습니다.
