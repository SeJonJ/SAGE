# SAGE overlay 전달 통합 재설계

> **후속 권고안:** [2026-11-05 대상별 문맥 묶음 설계](2026-11-05-overlay-context-catalog-design.md). 이 문서의 선택 대상 사전 감지 방식, 표준 요청의 Fast 0바이트 조건, X3 필수 승격 판단은 후속 설계에서 재검토했다. 아래는 당시 초안과 반례를 보존한 기록이며 최신 구현 권고안이 아니다.

- 작성일: 2026-11-04
- 상태: 2026-11-05 실현성 점검 반영 — D1 현재 훅 안 반례 확인, D2 부분 관측, D3 독립 선택 출처 부재 재현. 전달 방식 재설계 필요
- 코드 기준: v1.3.6 / 8e17a88
- 확인한 로컬 실행 파일: Claude Code 2.1.318 / Codex CLI 0.166.0
- 위험 분류: 사용자 선언에 따라 L3. 제품 구현·실제 압축 통합 검증·구현 후 정식 독립 리뷰는 미실행.

> 최신 실행 근거와 착수 판단은 [2026-11-05 실현성 점검](2026-11-05-overlay-delivery-feasibility.md)을 우선한다. 이 문서의 기존 전달 방식은 확정안이 아니다. Codex 선택 UI의 실제 선택 정보가 현재 훅 입력에 없고, Claude SessionStart 단독 중단이 작동하지 않는 반례를 확인했다. 세 문제 통합 수정과 표준+Fast 상속 의미는 유지하되 제품 구현 착수 조건은 아직 충족되지 않았다.

## 1. 사용자 요구와 설계의 권위

사용자가 제공한 이슈 문서는 문제를 알리는 입력이다. 그 문서의 A/B/C/D, 문자 상한, 훅 수, 공수 추정을 구현 요구사항으로 승계하지 않는다.

이번 작업의 요구는 다음 세 가지다.

1. 공유 overlay가 압축 후 전달되지 않는 문제를 고친다.
2. 개인 overlay 전달이 모델의 자발적 CLI 읽기에만 의존하는 문제를 고친다.
3. Fast 스킬에도 안전하게 overlay를 사용할 수 있게 한다.

Claude Code와 Codex를 같은 개발 범위에 넣는다. 세 항목을 하나의 설계·구현·검증·릴리스 단위로 다루며, 하나라도 남으면 전체 완료로 표시하지 않는다. 내부 구현·시험 순서를 나누는 것은 허용한다. 일부 항목만 먼저 출시하고 나머지를 후속 이슈로 넘기는 것은 이번 완료 조건에 맞지 않는다.

필수 수정과 추가 후보를 구분한다. 추가 후보는 위험도·중요도·재현 근거를 평가하고, 필수 문제 해결 또는 회귀 방지에 필요한 최소 범위만 승격한다. 새로 발견한 문제라는 이유만으로 포함하지 않는다.

이 문서는 제품 설계 초안이다. SAGE 엔진이 자기 변경을 승인하는 데 SAGE gate/review/waiver를 사용하지 않는다. 사용자는 확인 완료·설계 확정 후 즉시 개발을 승인했다. 그 조건이 충족되면 별도 작업 브랜치와 일반 검증·독립 리뷰로 진행한다. 커밋·푸시·머지·배포를 승인한 문서가 아니다.

## 3. 수정의 최소 경계

| ID | 반드시 해결할 내용 | 재사용을 우선할 부분 | 완료에 필요한 증거 |
|---|---|---|---|
| M1 | 공유·개인 본문을 검증 후 동일한 전달 계약으로 제공 | 기존 자격·경로·완화 검사, `load_local`, 공유 읽기/블록 함수 | 표준/Fast 각 대상에서 실제 본문과 해시 대조. 안내문·경로만 있으면 전체 전달로 세지 않음 |
| M2 | 압축·재개 뒤 필요한 지침을 복구 | 기존 SessionStart, IO adapter, compact reentry | Claude/Codex의 수동·자동 압축과 재개 다음 요청에서 본문 확인 |
| M3 | Fast 3종의 overlay 자격·표준 규칙 자동 상속·안전 경계 정렬 | 기존 Fast oracle, BACKING 메타테스트, 쓰기 가드 | 표준+Fast 공유/개인 병합, fresh open·convert·review·completion 적대적 시험 및 렌더/분류 일치 |
| M4 | M1~M3에 직접 필요한 설치·root·위임 호환성 | 명시적 scope, 기존 설치 transaction, 본문+ref packet, headless reviewer packet | Codex 전역/로컬 격리, worktree root, 실제 worker 전달, 업그레이드 왕복 |

M4는 설치 체계나 에이전트 프레임워크 전체를 다시 만드는 항목이 아니다. M1~M3가 기존 지원 경로에서 작동하는 데 필요한 연결만 바꾼다.

### 대상과 경로

- 표준 스킬 4종: sage-cycle, sage-plan, sage-team, sage-review.
- Fast 스킬 3종: sage-cycle-fast, sage-plan-fast, sage-team-fast.
- 기존 허용 worker 4종: leader, reviewer, implementer-a, implementer-b. 현재 packet 전달을 유지하고, 이를 이번 변경이 깨뜨리지 않게 한다.
- Claude는 SAGE가 설치하는 프로젝트 로컬 스킬, Codex는 현재 지원하는 전역·프로젝트 로컬 scope를 대상으로 한다.
- 로컬 CLI를 기본 실측 경로로 삼는다. 동일 로컬 runtime을 사용하는 다른 표면은 실행 근거가 확보된 범위만 호환성을 표시한다. 임의의 cloud/원격 제품 표면 지원 추가는 비범위다.
- hook 미신뢰·비활성·필수 기능 부재는 작동한다고 표시하지 않는다. 사용자/조직 정책을 우회하거나 임의로 신뢰 설정을 변경하지 않는다.

## 4. 변경하지 않을 경계

1. 개인 본문을 공유 파일·전역 스킬·manifest에 굽지 않는다. 기존 ignore·보존 계약을 유지한다.
2. overlay로 CORE의 필수 gate·실제 위험도·검증·리뷰 조건을 낮추지 못한다.
3. 전역 스킬의 위치와 현재 프로젝트 root를 같은 것으로 취급하지 않는다. 다른 체크아웃의 overlay를 섞지 않는다.
4. 전체 개인 inventory 검사와 기존 blocked 자산 경계를 기본적으로 유지한다. Fast 3종 이외의 자격 확대는 하지 않는다.
5. worker packet의 본문을 ref만으로 바꾸지 않는다. headless review의 기존 1회 로딩 예외를 유지한다.
6. 새 활성화 DB·세션 이력 관리자·대시보드·범용 감사 시스템을 만들지 않는다. 단, 선택한 대상의 재전달을 위한 최소 세션 영수증은 아래의 제한된 정책 변경 후보로 분리한다.
7. 큰 입력을 자동 요약·삭제·수정하여 크기를 맞추지 않는다.
8. 전달 성공과 LLM의 준수는 다르다. 준수를 완전히 강제하는 새로운 실행 엔진은 만들지 않는다.

## 5. 공통 전달 계약

입력은 명시적인 checkout root, host, scope, 자산 대상과 호출 시점이다. 기존 검사 함수를 경유해 공유·개인 본문을 읽고, 순서와 사실 서술형 경계를 붙여 host adapter에 제공한다.

우선순위는 필수 CORE·gate > 공유 overlay > 개인 overlay다. Fast 호출에서는 아래 확정된 대응 표에 한해 표준 자산의 규칙을 함께 적용한다. 서로 다른 역할의 문장을 무조건 공통 규칙으로 합치지 않는다.

root는 해당 호출의 작업 checkout으로 검증한다. `CLAUDE_PROJECT_DIR`나 스킬 파일 위치 하나만을 보편적인 root 근거로 사용하지 않는다. 동작 중 root 변경, 복수 후보, 잘못된 명시 root는 추측으로 해결하지 않는다. 범용 root resolver 전면 통합 대신 이 전달 경로의 경계만 고친다.

| 전달 시점 | root 근거 | 실패·불일치 처리 |
|---|---|---|
| startup / resume / compact | 그 이벤트가 제공한 cwd에서 기존 프로젝트·Git 경계를 검사 | 세션 최초 cwd를 캐시해 재사용하지 않음. profile/manifest가 확인되지 않거나 root 후보가 충돌하면 미전달 진단 |
| 명시 CLI / 위임 packet | 검증된 명시 `--root` 또는 발신 packet의 checkout root | 스킬 설치 위치를 대용하지 않음. 수신 실행 위치가 다른 checkout이면 부모 root를 조용히 승계하지 않음 |
| 세션 도중 worktree·checkout 이동 | host가 제공하는 새 이벤트 cwd와 해당 작업의 명시 workdir/root | 이동 후 첫 SAGE 작업 전에 새 root에 묶인 전달 확인 필요. adapter가 이 경로를 관측·복구할 수 없으면 D1 실패이며 정상 지원으로 표시하지 않음 |

개인 파일은 checkout별 소유다. worktree에 파일이 실제로 없고 root 검사·inventory 읽기가 성공하면 **그 checkout의 개인 지침 없음**이다. 부모 checkout의 개인 내용을 복사하거나 숨겨서 상속하지 않는다. root/읽기/기능 오류 때문에 못 읽은 경우는 없음(null)으로 바꾸지 않는다.

본문과 hash는 같은 읽기에서 생성한다. 원본 정규화 hash와 wrapper를 포함한 전달 payload hash를 혼동하지 않는다. 기존 content를 다시 읽어 과거 사용을 재구성하지 않는다. 새 관측 기록이 필요하면 기존 packet/로그에 최소 필드를 추가하며 개인 본문을 영속 공유 산출물에 남기지 않는다.

준비 상태(설정·자격·크기 검사), 실행 관측(loader의 출력), 검증 결과(실제 다음 모델 요청의 본문 확인)를 구분한다. 정적 doctor 검사만으로 DELIVERED/VERIFIED를 선언하지 않는다. 입력 오류, 기능 미지원, 출력 초과는 기존 CLI 진단 틀 안에서 이유와 영향을 명시한다. 별도 상태 관리 제품은 필요하지 않다.

전달 예산에는 CORE 필수 지침, wrapper, 공유·개인 합계, 같은 이벤트의 다른 문맥을 포함한다. 6,000/9,000자 중 하나를 근거 없이 기본값으로 선택하지 않는다. 유효한 지원 크기 안에서는 본문이 통째로 전달되어야 한다. 초과 시 경고와 수동 읽기 안내만 주고 해당 회귀가 해결됐다고 세지 않는다.

지원 크기 숫자는 아래 D2 실측 후 확정한다. 제보된 1만 자 규모의 개별 공유 overlay를 합성 원문으로 가정한 대표 fixture를 포함하여, 작은 sentinel만 통과하는 설계를 배제한다. 실제 원문과 합성 fixture를 구분해 기록한다.

Codex 전달 handler의 `additionalContextLimit` 설정은 훅 신뢰 우회와 다르다. 필요한 명시 상한을 SAGE 소유 등록 항목에 설정하는 최소 변경은 M2/M4 범위에 포함한다. 기존 사용자 handler나 전역 정책은 수정하지 않으며, 변경된 정의의 host 신뢰 검토는 그대로 따른다. 무제한(0)을 기본값으로 쓰지 않는다. 합산 payload가 지원 상한을 넘으면 한 슬롯을 빼거나 미리보기로 전달 성공을 선언하지 않는다.

디스크 합성과 런타임 payload의 역할을 구분한다. **Fast 3종은 overlay 자격을 열어도 공유 블록을 SKILL.md에 합성하지 않는 payload 전용 대상**으로 설계한다. 자격 허용과 물리 합성 여부를 같은 bool로 취급하지 않으며, Fast의 `expected_block`·sync·L1·validate가 이 전달 정책에 맞게 수렴하도록 M3에 포함한다. CORE 본문은 설치하고, 네 슬롯은 검증된 실행 payload로만 전달한다. 기존 설치에 관리 블록이 있다면 소유권·base 앵커를 확인한 관리 구간만 정리하며 사용자 본문은 덮지 않는다.

표준 4종의 기존 공유 디스크 합성은 호환성을 위해 유지한다. 개선 경로의 전체 payload는 checkout root·대상 범위·출처와 hash로 식별한다. 과거 렌더·압축 사본과 신규 전달분의 **문맥 내 중복을 제거했다고 주장하지 않는다**. D1/D2는 잘린 옛 사본과 전체 재전달분이 함께 있어도 현재 출처를 식별하고 전체 본문을 쓸 수 있는지 시험한다. 실패하면 해당 스킬의 중복 채널을 없애는 최소 합성/렌더 변경을 M1/M2로 포함하며, 이 변경 없는 상태로 출시하지 않는다.

기존 SessionStart를 재사용할 때 신규 개인/상속 payload 오류 때문에 기존 06 baseline이나 재진입 문맥 생성을 건너뛰는 early return을 추가하지 않는다. 독립 단계 결과를 모아 host adapter의 단일 응답으로 조립한다. Codex에 서로 독립된 JSON 문서를 연속 출력하지 않는다. 오류는 개인 본문 없는 진단으로 합치고, 해당 host의 실제 지원 중단 응답과 연동한다. 단순 stderr·exit 2가 모든 SessionStart에서 작업을 차단한다고 가정하지 않는다. host가 중단을 보장하지 못하면 그 경로를 검증 성공으로 세지 않는다.

구체적으로 현재 `run_session_start_snapshot`의 공유 L1 오류 후 조기 반환도 이 조립 경로에서 정리한다. 공유 입력 오류·L1 쓰기 실패·개인 오류 각각이 baseline·재진입 단계까지 생략하지 않게 독립 결과를 수집한 뒤 최종 중단을 결정한다. baseline의 기존 write-once·오류 의미를 바꾸거나 실패한 검사를 성공으로 승격하지 않는다. 이는 신규 복구 채널이 기존 조기 반환에 가려지는 직접 원인을 고치는 M2의 최소 변경이다.

일반 root 세션의 지침 묶음과 worker/reviewer packet은 별개다. root 묶음에는 worker 4종 본문을 한꺼번에 넣지 않는다. SAGE가 실행하는 headless review/cross-check는 런처가 명시한 packet 전달 문맥을 사용하여 기존 reviewer 1회 로딩을 유지한다. 이 문맥 표지는 출처·중복 억제용이며 gate 면제 권한이 아니다. 불명확한 자식 세션을 root로 추측해 오케스트레이터 지침을 주입하지 않는다. 이 구분이 실제 런처·재개 경로에서 성립하는지 D1/DC4로 확인한다.

입력 검증이 실패하면 그 실행의 공유·개인 성공 payload를 함께 내지 않는다. 이 원칙은 **새 payload 채널의 원자적 결과**를 뜻하며 이미 존재하는 표준 디스크 사본이나 host 과거 문맥을 지웠다는 뜻이 아니다. 따라서 디스크 공유만 남은 상태에서도 그 실행이 계속되지 않는 **지원 제어 지점의 native 차단**을 필수로 확인한다. 기존 복구·baseline 결과는 별도로 보존하고, 본문 없는 실패 코드와 중단 응답을 한 번 조립한다. Codex의 exit 0 JSON `continue:false`는 startup 요청 0건을 실측했지만 compact/resume은 미확인이다. Claude SessionStart의 같은 출력은 요청을 중단하지 못했고 UserPromptSubmit의 `decision:block`은 해당 입력 요청을 중단했다. Claude는 다른 지원 제어 지점의 최소 연결을 설계해야 하며 자동 압축 뒤 모델 요청 차단과 제품 도구 실행 차단을 구분해야 한다. **STOP 산문을 읽고 모델이 멈춘 표본만으로 결정론 중단을 입증하지 않는다.** 필요한 경계에서 native 차단을 제공하지 못하면 D1/DC6 미충족으로 제품 구현 확정을 중지한다. 알려진 한계로 적는 것만으로 이 경로를 정상 지원에 포함하지 않는다.

공유 검사는 `expected_block` 호출 하나로 대체할 수 없다. 그 함수는 경로·전체 inventory·완화 lint 전부를 검증하는 공개 경계가 아니다. 기존 `preflight_overlays`와 개인 `_read`의 검사항목을 유지하는 공통 수집 경계에서 본문을 한 번 읽어 메모리에 보관하고, 그 **같은 문자열**을 검사·hash·payload에 사용한다. 대상마다 `load_local`을 반복해 전체 inventory를 여러 번 읽는 방식은 피한다. 경로/자격/예약 토큰/완화 검사와 기존 전체 inventory 실패 의미를 바꾸지 않고 재사용한다. 수집 중 파일·목록 변화가 감지되면 한 번만 다시 수집하고, 재시도도 불안정하면 본문 없이 실패한다. 읽기 이후 발생하는 임의 편집을 무한 감시하거나 파일 잠금 서비스로 막는 것은 비범위다.

같은 SessionStart의 L1 표준 디스크 렌더와 payload도 **이 한 수집 결과를 소비**한다. L1이 `expected_block → overlay_text`로 별도 재읽기를 하고 payload가 다시 읽는 기존 경로를 그대로 병렬 사용하지 않는다. 설치/sync처럼 독립 호출된 명령은 각각의 수집 경계를 가지며, 이전 호출의 메모리 snapshot을 재사용하지 않는다. A→B 편집 시험은 L1과 payload 사이의 편집도 포함한다.

현재 요청의 검증된 전체 payload가 있으면 새 렌더는 개인 CLI를 별도로 다시 실행하도록 지시하지 않고 그 payload의 content/ref를 사용한다. 기존 산문을 그대로 두어 두 읽기 경로를 상시 중첩하지 않는다. 지원 경로에 payload가 없거나 현재 요청의 선택 정보와 맞지 않으면 기존 수동 CLI 읽기를 향상된 전달의 성공으로 대체하지 않는다. 이 최소 문구 변경과 host별 정상본 비교·base hash 갱신은 M1/M4에 포함한다.

각 payload는 session/request에 묶인 식별자, checkout root, 호출 대상과 출처별 hash를 가진다. 같은 출처의 내용이 A에서 B로 바뀌면 **현재 요청 경계에서 성공한 B 전달분**이 이후 사용에 유효하며 과거 A는 역사적 관측이다. 시간 문자열이나 파일 mtime만으로 최신을 고르지 않는다. 현재 경계의 B 검증이 실패하면 예전 A로 계속하는 fallback은 금지한다. 같은 요청의 동일 출처에 서로 다른 hash가 들어오면 조립 오류로 실패시킨다. Phase 05 ref는 각 작업/위임에 실제 제공한 payload의 ref를 사용하고, 나중에 다시 읽어 대표 hash 하나로 과거를 덮지 않는다. source 편집 후 반영 시점은 다음 지원 전달 경계이며, 실행 중 임의 시점의 hot reload를 약속하지 않는다.

## 6. 구현 방향과 설계 결정 시험

공통 검사·본문 구성은 한곳에서 유지하고, host별 전달 부분만 연결한다. 최종 모듈명과 세부 함수 분리는 구현자가 정한다. 핵심 gate의 standalone 실행 성질은 보존하고 검증 로직을 두 벌 복제하지 않는다.

D1~D3는 별도 출시 단계가 아니라 같은 통합 설계를 확정하기 위한 시험이다. 미실행·불명확이면 그 상태를 남기며 제품 구현 계획을 확정하지 않는다. 초기 시험으로 작은 fixture만 확인한 결과를 큰 입력·자동 압축·다른 host의 근거로 재사용하지 않는다. 2026-11-05에는 D1의 선택 UI 및 startup 중단 반례, D2의 합성 큰 입력 spill/한도 차이, D3의 기존 CLI 확인 출처 부재를 관측했다. 전체 D1~D3 PASS는 아니며 실제 압축·재개·악성 네 슬롯의 모델 행동 검증은 미실행이다.

세 시험 모두 통과하면 근거와 수치로 전달 수단·예산을 확정한다. 실패 시 상태 저장량이나 대상 수를 자동 확대하지 않는다. 최소 대안과 필요한 정책 변경을 설계에 반영하며, 결정이 나지 않으면 **통합 설계 미확정으로 정지**한다. 이는 일부 기능을 남겨두고 출시하는 fallback이 아니다. 현재 문서는 이 결정 절차까지 정한 설계이며 구현 가능한 전달 알고리즘이 확정됐다는 문서가 아니다.

| 직접 실행된 표지 없는 headless | 오주입 방지 시험 필수 | root/role을 추측하지 않음. SAGE 작업 진입이 확인되면 식별·차단 연결을 검증하고, 일반 비SAGE 실행에는 임의 payload를 주입하지 않음 |
| compact/resume/worktree 이동 후 첫 SAGE 작업 | 양 host 필수 | 위 진입에서 확정한 명시 현재 대상과 새 이벤트/root. 다른 세션/checkout 영수증의 무조건 승계 금지 |

허용 신호는 ① host가 실제 호출을 해석해 제공한 자산 필드, ② SAGE 런처의 결합된 handoff, ③ host의 실제 자산 해석과 동등함을 부정·중첩·scope·버전 fixture로 검증한 제한된 parser/adapter다. 사용자 문장에 `$sage-team`이라는 문자열이 있다는 것만으로는 ③이 아니다. 모델이 실행한 영수증 명령은 앞선 허용 신호와 결합됐을 때만 전달 결과 관측에 사용할 수 있고, 대상 선택의 유일한 근거로는 금지한다.

Codex에서 위 필수 경로의 입력 연결이 불가능할 수 있다는 위험을 명시한다. 2026-11-05 같은 Text와 다른 구조화 Skill 선택을 사용한 실제 app-server 시험에서, 모델 요청에는 선택별 본문이 들어가지만 훅 prompt와 필드에는 그 선택 정보가 없음을 확인했다. 따라서 **현재 훅 입력만 읽는 parser/영수증 방식은 선택 UI의 최초 전달을 해결하지 못한다.** 현재 host 기능과 최소 SAGE adapter만으로 전체 요구를 충족할 수 있다고 주장하지 않으며, 구현을 크게 시작하기 전에 D1 실패로 보고해 대안을 재설계한다. 원문 읽기 의존을 영수증 쓰기 의존으로 옮기거나 암묵 경로를 조용히 제외하는 것은 통과 경로가 아니다. 비SAGE 대화·작업 자체를 이 overlay 기능이 일괄 차단하는 설계도 아니다.

### 최소 대상 영수증의 제한된 정책 결정

7종 전체 주입은 사용자 확정 요구인 일반 실행의 역상속 없음과 맞지 않으므로 제외했다. compact 이벤트 자체에 대상이 없다는 사실도 확인했으므로, **host가 이미 보존하는 호출/위임 식별자를 재사용하거나 선택 대상의 최소 영수증을 보존하는 연결**을 필수 설계 결정으로 다룬다. loader의 상태 없는 읽기는 유지한다. 별도 영수증을 보존해 재전달 대상을 정하면 종전의 활성화 상태 없음 범위를 변경하는 것이므로 이를 단순 로그라고 이름만 바꿔 숨기지 않는다.

허용을 검토하는 필드는 session/request 식별자, 검증한 checkout root, 명시된 대상/role, 전달 payload id·출처 hash, 상위 handoff 식별자뿐이다. 개인 본문, 자유 서술 승인문, TTL 기반 자동 승인, 전역 이력 DB는 넣지 않는다. root/role/target 정보가 사라지거나 맞지 않으면 최근 phase나 마지막 파일을 골라 복구하지 않는다. 새 session·fork·worktree 이동은 기존 영수증의 무조건 재사용 조건이 아니다. 중첩 호출의 진입·복귀·Fast 전환을 실제 식별할 수 있는지는 D1의 차단 조건으로 남긴다. 정확한 원자적 갱신·수명·소유 경계는 D1의 관측 결과로 확정하고, 필요 없는 필드는 추가하지 않는다.

영수증을 도입한다면 한 session/실행 문맥의 **현재 선택 포인터 하나**를 명시 진입마다 원자적으로 교체한다. 파일의 최신 mtime이나 누적 이력에서 대상을 고르지 않는다. 중첩은 상위 handoff에만 연결하고 명시 복귀 때 검증한 부모 대상으로 교체한다. 종료·새 명시 호출은 이전 선택을 대체/해제하며, 지연된 자식 결과가 새 선택을 덮지 못하게 해당 handoff/payload id를 대조한다. 복귀 신호가 없으면 child의 마지막 대상을 현재라고 추측하지 않고 재전달 실패로 처리한다. 이 수명 규칙을 실제로 구현할 신호가 존재하는지는 D1 미지수다.

표지 없는 세션의 기본값은 **대상별 payload 미주입**이다. 단순히 표지가 없다고 root 작업이라고 추측하지 않는다. 기존 SAGE 진입 경로에서 이 기본값을 지나려면 native 호출 정보나 SAGE가 발행한 명시 handoff로 대상을 확정하는 최소 연결이 있어야 한다. 직접/암묵 스킬 호출을 조용히 지원 범위에서 빼고 성공을 선언하지 않으며, 필요한 입력 연결을 확보하지 못하면 D1/DC1~DC4 미충족이다.

일반 실행의 역상속 없음은 **새로 구성하는 유효 payload**에 Fast 출처를 넣지 않는다는 뜻이다. 이미 Fast를 실행했던 세션의 과거 메시지까지 지웠다는 뜻은 아니다. host가 보유한 과거 문맥을 삭제하는 새 기능은 만들지 않는다. 과거 Fast/다른 hash가 남아 있는 전환 시험에서는 현재 root·대상·payload id와 과거 출처의 비활성 관계를 명시하고, 이것이 실제 전달·사용 구분에 충분한지 D2의 반례로 확인한다. 이를 통과하지 못한 채 단순 구성 함수의 0바이트 검사만으로 DC3를 통과시키지 않는다.

### 확정된 사용자 의미 결정: 표준 + Fast 자동 상속

사용자가 두 overlay를 모두 적용하는 방향을 선택하고 설계 반영을 지시했다. 이전의 자동 상속 없음 임시 가정을 폐기한다. **Fast 호출에서는 대응 표준 overlay를 상속하고 Fast 전용 overlay도 추가 적용한다.** Claude Code와 Codex, 공유와 개인에 동일하게 적용한다. 파일 복사·이행·원문 수정은 하지 않고 실행 시 적용 대상을 구성한다.

| 호출 대상 | 함께 적용하는 표준 대상 | 추가 적용하는 Fast 대상 |
|---|---|---|
| sage-cycle-fast | sage-cycle | sage-cycle-fast |
| sage-plan-fast | sage-plan | sage-plan-fast |
| sage-team-fast | sage-team | sage-team-fast |

일반 스킬 호출은 자신의 overlay만 적용하며 Fast overlay를 역으로 상속하지 않는다. sage-review는 별도 Fast 대응 자산을 만들지 않고 기존 호출·overlay 경로를 유지한다. 우산 스킬이 plan/team으로 위임하면 각각의 대응 쌍을 적용하며, 우산이라는 이유로 모든 표준/Fast 자산을 하나의 공통 규칙으로 합치지 않는다.

검사 순서는 **호출된 대상(Fast id)의 자격 → 각 상속 출처의 자격·입력 검증 → 네 슬롯 구성**이다. Fast 대상이 blocked면 표준 출처가 compose여도 그 Fast 문맥에는 상속분을 우회 전달하지 않는다. 전체 묶음 후보에서도 blocked 대상을 위한 활성 지침을 구성하지 않는다. Fast 개방은 BACKING과 적대적 시험이 갖춰진 뒤 분류·쓰기 가드·spec을 함께 갱신하는 M3 변경이다.

Fast 자격 허용은 디스크 합성을 허용한다는 뜻이 아니다. payload 전용 정책과 일치하는 설치·sync·L1·validate를 함께 시험하며, Fast SKILL.md의 부분 공유 사본을 별도 전달 경로로 남기지 않는다.

한 대응 쌍의 본문 전달 순서는 다음과 같다. 이는 기존 공유 > 개인 우선순위를 유지하기 위한 구성 순서이며, 뒷문장이 앞문장을 무조건 덮어쓴다는 뜻이 아니다.

1. 공유 표준 overlay
2. 공유 Fast overlay
3. 개인 표준 overlay
4. 개인 Fast overlay

Fast 전용 파일이 없어도 표준 규칙을 적용한다. 표준 파일이 없으면 Fast 전용 규칙만 적용한다. 둘 다 없으면 추가 지침 없음으로 처리한다. 빈 파일은 기존 loader의 없음 의미를 유지하고, 오류 입력은 기존 검증 정책대로 실패시킨다. 네 슬롯과 wrapper 합계를 전달 크기에 반영하며 일부를 생략하고 전체 상속이 완료됐다고 표시하지 않는다.

정상적인 경우에는 표준·Fast 규칙을 모두 지킨다. Fast 전용이라는 이유만으로 표준 규칙이나 필수 CORE를 완화하지 못한다. 우선순위로 해결되는 충돌은 해당 우선순위를 따르고, 같은 층에서 양립할 수 없는 규칙이나 표준 전용 절차와 Fast 절차의 충돌을 발견하면 임의 무시·자동 재작성 없이 해당 진행을 멈추고 사용자에게 확인한다. 모든 의미 충돌을 자동 검출하는 새 분석기는 범위에 넣지 않는다. 대표 충돌 사례는 행동 smoke에 포함한다.

wrapper에서 CORE는 **현재 호출된 스킬의 CORE**를 뜻한다. 표준 overlay를 상속했다고 표준 사이클의 물리 Phase 01~04 문서 생성까지 강제하는 것은 아니다. 그런 지침이 Fast CORE와 충돌하면 자동으로 composite 섹션 지침으로 번역·완화하지 않는다. 대화형은 충돌을 보고해 사용자에게 원문 정리를 요청하고, 비대화 worker/reviewer는 해당 작업을 BLOCKED로 상위 호출자에게 반환한다. 모델이 모든 의미 충돌을 탐지한다는 보장은 하지 않으며 일반/비대화 대표 사례를 별도 행동 시험으로 남긴다.

중복은 한 전달 묶음 안의 동일 논리 출처(checkout root, 공유/개인 층, kind, asset id)를 기준으로 방지한다. 본문이 같다는 이유로 서로 다른 파일을 임의로 하나로 합치지 않으며, 각 출처와 hash를 유지한다. 압축·재개 후의 의도적인 재전달은 중복 오류가 아니다. 기존 packet과 headless reviewer의 1회 로딩 경계도 유지하며, 이 조건 때문에 별도 전역 활성화 이력 DB를 만들지 않는다.

필수 시험에는 네 슬롯 동시 존재, 표준만/ Fast만/모두 없음, 빈 파일, 검증 오류, 일반 호출의 역상속 없음, 우산 위임의 중복 방지, 공유 > 개인 순서, 합산 크기 경계, 압축·재개 후 네 슬롯 복구를 포함한다. 현재 이 절은 확정된 요구와 설계이며 구현·실행 결과가 아니다.

## 7. 추가 후보의 위험도·중요도·재현 근거 평가

위험도는 잘못 동작할 때의 영향, 중요도는 M1~M4 달성에 미치는 정도다. 재현은 코드로 확인/격리 재현/host 실측/제보/미확인을 구분한다. 관측 수가 없으면 발생률을 수치화하지 않는다.

| ID | 추가 후보 | 위험도 / 중요도 | 현재 재현 근거 | 초안 처분 / 승격 조건 |
|---|---|---|---|---|
| X1 | CORE 본문 전면 축약·외부화 | 변경 회귀 중~높음 / 조건부 | 머리 삽입 시 손실 가능성은 확인. 개편 필요성은 미확인 | 전면 개편 제외. 선택한 전달 방식이 필수 STOP 지침을 밀어낼 때 해당 부분만 M2에 포함 |
| X2 | 활성화 상태/선택 이력 저장 | 세션·root 혼입 위험 높음 / 대상 복구에는 높음 | compact 대상 신호 부재와 7종 주입 반례는 코드/설계로 확인. Codex UI의 최초 선택 정보가 훅에서 소실됨은 실측 | 최소 영수증만으로 소실된 최초 선택을 복원하지 못함. 다른 신뢰 입력 연결을 먼저 확정하고 필요한 최소 수명만 결정. 전체 이력/DB는 제외 |
| X3 | Fast 사용자 선택 출처·최소 독립 floor | 미승인 보증 저하 영향 높음 / Fast 자격 개방에 필수 | 합성 fixture에서 실제 open이 확인 없이 성공하고 convert가 합성 확인자 문자열을 수용. 악성 네 슬롯 모델 행동은 미실측 | 자격 개방 전 최소 보완 설계를 필수로 승격. 인자 문자열 검증을 사람 동의의 보증으로 쓰지 않음. 구체 수단 미확정이며 일반 승인 시스템 전면 개편은 제외 |

| X5 | 개인 inventory 검증을 요청 자산만으로 축소 | fail-closed 완화 위험 높음 / 이번 목표에는 낮음 | 타 파일 오류의 요청 실패 격리 재현. 기존 의도된 계약 | 제외. 현재 검사 유지와 오류 영향 안내만 포함 |

추가 후보를 포함할 때는 같은 설계 문서에 원인·최소 변경·추가 수용 조건·증거를 기록한다. 위험도 높음만으로 자동 포함하지 않는다. 반대로 필수 수용 조건을 막는다고 확인된 항목은 추가로 남겨두고 출시하지 않는다.

| DC1 | 공유 overlay가 지원 크기에서 최초·압축·재개 뒤 전체 전달됨 | 양 host의 실제 다음 요청 본문. 본문 뒤쪽·hash, 과거 잘린 렌더와 전체 전달분의 혼재 포함 확인 |
| DC2 | 개인 overlay가 같은 시점에 자발적 raw/CLI 읽기에만 의존하지 않고 전달됨 | 실제 전달 경로, 누락/오류/없음/큰 입력 시험. 개인 원문 보존·공유 산출물 비노출 |
| DC3 | Fast 3종에서 표준+Fast overlay를 공유·개인 모두 상속·추가 적용하고 안전 경계 유지 | 분류·spec·render·쓰기 가드 정렬, 네 슬롯·부재·현재 일반 payload의 Fast 본문 0바이트·신규 일반 요청과 과거 Fast 전환의 구분·중복·합산 크기·우선순위 시험, 표준 상속 출처까지 포함한 Fast BACKING, fresh/convert/review/completion 우회 시험 |
| DC4 | Codex global/local, checkout/worktree와 위임에서 동일 계약 유지 | 두 프로젝트와 worktree 격리, 개인 파일의 정상 부재와 오류 구분, 실제 worker·headless reviewer packet과 재개 격리. 전역 산출물에 프로젝트 원문 없음 |
| DC5 | 기존 gate·검증·설치 수명주기를 약화하지 않음 | 본문/단위/통합 회귀, Fast payload 전용·표준 L1/payload 동일 snapshot, sync 멱등성·base hash, install/upgrade/rollback 보존, 기존 표준 overlay가 있는 업그레이드 직후 첫 Fast 호출, clean candidate package consumer |
| DC6 | 실패·미지원·준비·관측·검증을 정직하게 구분 | hook 비활성/미신뢰/구버전/출력 초과의 최소 진단. 공유 입력 오류·L1 쓰기 실패·개인 오류 각각+compact에서 baseline·재진입 보존, 단일 응답, native 중단 및 오류 후 제품 작업의 잘못된 계속 0건 확인. 설정만으로 전달 완료 선언 없음 |

DC1~DC6은 하나의 AND 조건이다. Fast를 blocked로 남기거나 Codex를 범위 밖으로 빼고 완료하지 않는다. 미지원 설정을 명확히 안내하는 것은 필요하지만, 요청된 정상 지원 경로를 구현하는 것을 대신하지 못한다.

LLM의 지침 준수는 별도 행동 smoke로 확인한다. 압축 요약에 규칙이 남아 있어서 따랐던 것과 원문 전달을 구분한다. 전달 검증과 준수 검증을 같은 수치로 합치지 않는다.

## 9. 검증 규모의 제한

전 조합을 매번 곱한 대규모 시험 체계를 새로 만들지 않는다. 결정론 조합은 기존 단위·통합 fixture로 폭넓게 확인하고, 실제 host 시험은 각기 다른 실패 경로를 대표하는 시나리오로 묶는다. 실패 또는 새 연결 변경이 생긴 부분만 추가 반복한다.

필수 host 시나리오는 Claude 표준/개인·수동/자동 압축, Codex 전역/로컬·압축/재개, Fast fresh/convert, 위임과 checkout/worktree 전환, 지원 상한 경계·권한/신뢰 실패다. 각 관측에는 host 버전·후보 package/렌더 신원·fixture 크기·호출 방식·결과를 남긴다. 운영 실패율과 표본 smoke 결과는 구분한다.

업그레이드 fixture에는 새로 만든 악성 Fast 파일만 쓰지 않고 **기존 표준 공유·개인 파일이 처음 Fast에 상속되는 경로**를 넣는다. upgrade/doctor의 기존 진단 출력에서 새로 상속되는 표준 출처 경로와 Fast 대응을 본문 없이 안내한다. 승인자·확인값·렌즈 지침이 새 문맥에서 만드는 영향은 D3/X3로 판정한다. Fast 필드명을 lint에 단순 추가하는 것만으로 사용자 동의를 보증했다고 세지 않는다.

공수·파일 수·성능 저하는 D1~D3 결과와 확정 diff 범위 전에는 추정치를 완료 근거로 제시하지 않는다.

## 10. 다음 설계 단계와 아직 하지 않은 것

현재 산출물은 범위, 불변식, 추가 후보 평가, 설계 결정 시험, 확정된 Fast 자동 상속 의미, 공통 완료 조건이다. D1~D3의 최소 시험 결과를 반영해 이 문서를 구현 가능한 설계로 갱신한다. 그 뒤 같은 범위의 구현 계획을 작성한다.

제품 코드, 설치 설정, 개인 overlay, 원본 제보 문서는 변경하지 않았다. 이 초안은 기술 결정 시험·제품 구현·실제 압축 smoke·독립 L3 리뷰·릴리스 완료를 주장하지 않는다.

### 초안의 구현자 관점 검토

2026-11-04에 작성 문서만 전달한 별도 에이전트의 읽기 전용 builder check를 1회 받았다. 추가 사용자 의미 결정으로 Fast 별도 파일(A)과 표준 규칙 상속(B)의 선택을 지적했다. 후속 사용자 결정으로 B(표준+Fast 모두 적용)를 확정하여 반영했다. 이 초기 검토는 다음 Claude 리뷰와 별개이며 정식 L3 리뷰가 아니다.

### 사용자 요청에 따른 Claude 적대적 리뷰 3회

자동 상속 반영 설계 → 1차 지적 반영 설계 → 2차 지적 반영 설계를 각각 새 Claude 세션에 제공해 적대적 리뷰를 3회 실행했다. 3차에서도 명세를 차단하는 지적이 나와 반영했다. 이후 2026-11-05에는 실측 결과와 그 수정본을 대상으로 추가 실현성 검토 1회를 받았으며, 현재 훅 안의 확정 불가 결론과 제안별 처분을 별도 기록했다. 원래 3회나 추가 검토를 무지적·설계 승인·구현 후 정식 L3 리뷰로 표현하지 않는다.

세부 지적, 채택/부분 채택/보류 이유, session·원문·입력 신원은 [리뷰 기록](2026-11-04-overlay-delivery-adversarial-review.md)을 따른다. 쉬운 그림 설명은 [ELI5 HTML](2026-11-04-overlay-delivery-eli5.html)에 있다. 2026-11-05의 추가 실현성 검토 및 실제 호스트 관측은 [점검 기록](2026-11-05-overlay-delivery-feasibility.md)을 따른다. 현재 상태는 **현재 전달 방식의 반례를 확인한 설계 재검토 단계이며 구현 착수 가능한 최종 알고리즘 승인 상태가 아니다**.
